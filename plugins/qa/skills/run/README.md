# /qa:run — 화면 QA

실제 브라우저로 화면을 눌러 보고, 확인할 기준마다 통과 여부와 두 폭(1280·390) 스크린샷을 리포트로 준다.
슬래시 명령으로만 실행된다. "QA 해줘"라고 말해도 저절로 돌지 않는다.

## 헤매지 않으려면

- **통과·실패 판정을 받으려면 기준이 있어야 한다.** 플랜의 `## QA 시나리오`나, 요청에 쓴 기대 결과가 기준이 된다. 둘 다 없으면 에러와 화면 깨짐만 본다.
- **플랜은 이번 작업의 계획에서 찾는다.** 대화에 있으면 그것을 쓰고, 없으면 티켓 키나 기능 이름으로 Claude Code 기본 플랜 위치(`~/.claude/plans/`)를 찾는다. 못 찾으면 경로를 직접 준다. 티켓 내용과 PR 본문은 읽지 않는다.
- **로컬로 볼 때는 개발 서버를 먼저 띄운다.** 대상을 안 주면 로컬로 본다.
- **배포 URL로 볼 때는 로그인 정보를 먼저 저장한다.** 처음 실행하면 저장 명령을 알려 준다. 자기 터미널에서 한 번 실행한다. Google·Meta 소셜 로그인은 안 된다.

## 이렇게 쓴다

```bash
/qa:run                                        # 구현을 마친 세션에서 바로. 대화에서 다룬 플랜으로 본다
/qa:run ~/.claude/plans/org-new-snug-otter.md  # 플랜을 집어서
/qa:run ABC-1234 https://stg.example.com       # 티켓 키로 플랜을 찾아 배포 화면에서
/qa:run 조직 생성, URL 넣으면 조직명이 채워져야 해   # 플랜 없이 기대 결과를 말로
```

## 시나리오 예시

정해진 양식은 없다. 화면에서 확인할 수 있는 기대 결과만 있으면 판정한다. 다만 아래처럼 대상·계정·흐름·수락 기준을 나눠 쓰면 매번 같은 기준으로 돌아서 좋다.

```markdown
## QA 시나리오

- 대상: 로컬
- 계정/역할: 조직이 없는 신규 사용자

### 흐름

1. 조직 만들기 화면에 들어간다
2. 웹사이트에 `https://www.yourbrand.com`을 입력한다
3. 목표를 고르고 만들기 버튼을 누른다

### 수락 기준

- 2단계 뒤 조직명에 "Yourbrand"가 자동으로 채워진다
- 3단계 뒤 다음 온보딩 단계로 넘어간다
```
