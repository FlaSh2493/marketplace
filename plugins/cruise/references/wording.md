# 산출물 문장 규약 (wording)

cruise 산출물의 **본문 문장**은 이 코드를 안 쓴 사람이 읽는다 — 동료 개발자, 리뷰어, 배포 담당,
기획자, Jira 이슈를 보는 사람. 팀 PR 규약(`pr-summary` skill)과 같은 말투를 쓴다.

적용 대상:

| 대상 | 독자 |
|------|------|
| `plan.md` `## 요구사항` R 문장 | **Jira 댓글에 그대로 실린다** (log 의 `완료한 작업`·`미해결`) |
| `plan.md` `## 개정 이력` 요약 | 나중에 이 task 를 다시 보는 사람 |
| `summary.md` `## 개요` · `## 변경 파일` 설명 · `## 구현 현황` · `## 검증` | 30초 안에 "이 브랜치가 뭘 했나" 를 파악하려는 사람 |
| `result.md` 본문 | 비슷한 작업을 시작하려는 사람 |

적용 **안 하는** 곳 (개발자·에이전트 전용):

- `plan.md` `## 구현 계획` 의 작업 항목 · `생성/수정 파일` — 기술 서술이 맞다
- `plan.md` `## 검증 방법` 의 `도구/명령` 칸 — 명령 원문
- frontmatter · 헤딩 텍스트 · SKILL.md 지시문

---

## 1. 밖에서 보이는 변화로 쓴다

내부 구조가 아니라 **무엇이 가능해지는가 / 무엇이 달라지는가**로.

| ✗ | ○ |
|---|---|
| `useInfiniteQuery 로 커서 페이징 구현` | `목록을 아래로 내리면 다음 페이지가 이어서 나옵니다` |
| `FilterChips 컴포넌트 신규` | `카테고리를 골라 목록을 걸러낼 수 있습니다` |
| `EmptyState 분기 추가` | `보여줄 항목이 없으면 안내 문구가 나옵니다` |
| `zustand store 를 useSearchParams 로 대체` | `필터를 고른 상태가 주소에 남아, 새로고침하거나 링크를 공유해도 유지됩니다` |
| `BrandedGrid 에서 fetch 로직 분리` | `목록 화면과 데이터 불러오는 부분을 나눠, 화면만 따로 테스트할 수 있습니다` |

리팩토링처럼 밖에서 안 보이는 작업은 **무엇이 나아졌는지**로 쓴다 —
`동작은 그대로고, 앞으로 이 화면을 고칠 때 손댈 곳이 줄어듭니다`.

## 2. 말투

- **합니다체.** "~한다", "~하는 바" 대신 "~합니다", "~하면 됩니다"
- **전문용어는 풀어 쓴다.** 그대로 쓸 거면 괄호로 뜻을 붙인다
  - 커서 페이징 → `이어서 불러오기`
  - 스켈레톤 → `불러오는 동안 자리표시가 보입니다`
  - ARIA·a11y → `키보드만으로 조작할 수 있습니다`, `화면 읽기 프로그램이 읽을 수 있습니다`
  - SSR/CSR·hydration·memoization → 쓰지 말고 무슨 일이 벌어지는지로
- **컴포넌트·훅·함수·라이브러리 이름을 문장 주어로 쓰지 않는다.** 파일 경로가 꼭 필요하면
  `## 변경 파일` 처럼 경로 칸이 따로 있는 곳에만 둔다
- 한 항목 = 한 줄. 왜 그렇게 했는지는 **한 줄**만 붙인다

## 3. 안 한 것도 적는다

읽는 사람이 가장 먼저 의심하는 지점이다. `### 미지수`·`(철회: 사유)`·`## 비고` 가 그 자리다.

```
- [ ] R4: 정렬 기능 (철회: 이번에는 넣지 않습니다 — 필터부터 확인하고 다음에)
```

## 4. 자기검증 한 줄

산출물을 쓰기 전에 자문한다.

> **이 화면을 한 번도 안 본 기획자가 이 문장만 읽고 무엇이 달라졌는지 말할 수 있는가?**

말할 수 없으면 아직 내부 구조를 쓴 것이다.
