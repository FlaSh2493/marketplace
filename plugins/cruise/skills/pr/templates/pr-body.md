# PR 본문 템플릿

PR 본문은 **읽는 사람 기준**으로 쓴다. 읽는 사람은 이 코드를 안 쓴 동료, 리뷰어, 배포 담당, 기획자다.

## 섹션은 셋, 그 외엔 넣지 않는다

```markdown
## 1. 뭘 만들었나

**{이 PR 이 끝나면 무엇이 가능해지는가 — 한 문장. 내부 구조가 아니라 밖에서 보이는 변화로.}**

{지금까지는 이랬다 → 이 PR 이 그걸 바꾼다. 한두 줄.}

- {세부 변경}
- {안 한 것도 적는다 — "쓰기 도구는 안 열었다", "기존 응답 형식은 안 바꿨다"}

## 2. 코드 말고 따로 해줘야 하는 것

| 이름 | 값 | 어디에 |
|---|---|---|
| `FOO_URL` | 예시값 | 배포: Secrets Manager `{env}/svc/<서비스>/env`<br>로컬: 프로젝트 루트 `.env` |

- 우선순위 / 반영 시점 / 마이그레이션 실행 방식
- {추가 설정이 없으면} 환경변수·설정값은 하나도 추가되지 않습니다.

## 3. 이게 붙으면서 생길 수 있는 일

- {되는 경로와 안 되는 경로}
- {매 요청 늘어나는 비용}
- {기존 동작의 판정이 바뀌는 곳}
- {배포 순간의 영향 / 롤백 가능 여부}

{task.md 완료 조건이 있는 경우}
## 완료 조건

- [ ] {체크리스트 항목}

{이슈 키가 있는 경우}
Closes #{이슈 키}
```

설계 논쟁, 대안 검토, "함정이 셋이었습니다" 류의 서사, 커밋 히스토리, 코드 인용은 **넣지 않는다**.
그건 코드 주석과 리뷰 스레드의 몫이다.

---

## 1. 뭘 만들었나

- 첫 줄에 **한 문장 굵게** — 이 PR 이 끝나면 무엇이 가능해지는가. 내부 구조가 아니라 밖에서 보이는 변화로.
- 그 다음 "지금까지는 이랬다 → 이 PR 이 그걸 바꾼다" 한두 줄.
- 세부는 불릿. **안 한 것도 적는다** — 리뷰어가 가장 먼저 의심하는 지점이다.
- UI 변경이 있으면 Before/After 스크린샷·GIF 첨부.

## 2. 코드 말고 따로 해줘야 하는 것

**"무엇을" 만 쓰면 안 된다. "어디에" 가 항상 같이 나와야 한다.** 이게 가장 자주 빠지는 부분이다.

같이 적을 것:

- **우선순위** — 여러 곳에서 읽는다면 뭐가 이기는지 (예: Secrets Manager > 환경변수 > `.env`)
- **반영 시점** — 부팅 때만 읽는다면 "파드 재시작 필요"
- **비밀값은 어디에만 둬야 하는지**
- **상대 서비스 쪽 설정** — 우리 쪽만 켜서 되는 게 아니면 그쪽 변수명과 "값이 같아야 함" 까지
- **DB 마이그레이션** — 자동으로 도는지(배포 스크립트/entrypoint), 수동이면 명령어
- **부분 설정의 동작** — 하나만 넣으면 어떻게 되는지
- **설정 안 하면** 기존과 동일한지

**추가 설정이 없으면 "환경변수·설정값은 하나도 추가되지 않습니다" 라고 명시한다.** 섹션을 비우지 않는다.

변수명·시크릿 경로·마이그레이션 리비전은 **추측하지 말고 코드에서 확인**한다
(`config.py`, `.env.example`, `deploy/`, `migrations/`).

## 3. 이게 붙으면서 생길 수 있는 일

"이 기능이 추가되면서 생기는 부작용" 만. 코드 품질 자랑이나 향후 계획이 아니다. 챙길 것:

- **어떤 경로는 되고 어떤 경로는 안 되는가** (웹은 되고 Slack 은 안 됨 같은)
- **매 요청/매 턴 늘어나는 비용** (프롬프트 길이, 쿼리, 저장 계산)
- **기존 동작의 판정이 바뀌는 곳** — 조건문 하나가 바뀌어 다른 기능의 결과가 달라지면 반드시
- **배포 순간의 영향** — 락, 다운타임, 재작성, 롤백 가능 여부
- **데이터가 옛 것과 새 것으로 갈리는 것** — 백필 안 하면 소비자가 뭘 조심해야 하는지
- **막지 못하는 것** — 안내일 뿐 강제가 아닌 것, 집계에서 빠지는 것
- **앞으로 이걸 건드릴 사람이 밟을 함정** (파일 두 개를 같이 고쳐야 한다 등)

## 말투

- **문어체·서면체 금지.** "~한다", "~하는 바" 대신 "~합니다", "~하면 됩니다".
- **전문용어는 풀어 쓴다.** 그대로 쓸 거면 괄호로 뜻을 붙인다.
  - `jsonb`/GIN → "검색 가능한 형식", "색인을 걸어서 전체 훑기 대신 색인 조회"
  - ACCESS EXCLUSIVE 락 → "마이그레이션 도는 동안 이 테이블은 읽기도 쓰기도 막힙니다"
  - 컨테인먼트, 비정규화, 블라스트 레이디어스 → 쓰지 말고 무슨 일이 벌어지는지로
- 왜 그렇게 했는지는 **한 줄**로 붙인다. 문단으로 늘리지 않는다.
- 판단이 갈릴 결정은 "일부러 그렇게 했습니다" 를 붙여 실수와 구분한다.

## 부가 섹션

- **완료 조건** — `task.md` 가 있으면 그 완료 조건을 체크리스트로 3섹션 뒤에 붙인다. 없으면 섹션 생략.
- **Closes** — 이슈 키가 있으면 마지막 줄에.
